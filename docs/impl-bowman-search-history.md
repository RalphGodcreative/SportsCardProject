# Implementation Plan: 1st Bowman Search History

## Summary

Record every search on the 1st Bowman checklist page (`GET /bowman`) in a new
`bowman_search_history` table, so we can see **which players** and **which sets** people
look for, and **who** searched when they are logged in. Admins get a read-only page at
`/admin/bowman-searches` with the most-searched players and sets plus the latest searches.

| Route | Who | What |
|---|---|---|
| `GET /bowman` | everyone (already `permitAll`) | unchanged for the user; now also saves one history row per search |
| `GET /admin/bowman-searches` | `ROLE_ADMIN` | top players, top sets, latest searches |

No new security rule is needed: `/admin/**` is already `hasAuthority("ROLE_ADMIN")` in
`SecurityConfig`.

### Decisions

| Question | Decision |
|---|---|
| What counts as a search | Only requests where `BowmanChecklistController.search` actually runs a search (`byPlayer` or `bySet` is true). Opening `/bowman` with no params is **not** recorded. |
| Player vs set | One table with a `search_type` column (`PLAYER` / `SET`). The page runs exactly one of the two searches per request, so one row = one search. |
| Player text | Stored **trimmed, as typed** (max 100 chars, same as the input's `maxlength`). Reports group by `LOWER(player)` so "Ohtani" and "ohtani" count together. |
| Set fields | `year` and `set_name` stored separately, either may be null (the set search allows "any" for one of them). |
| Who searched | **`user_id`**, nullable. `NULL` = guest (not logged in). The username is shown via a join to `users`, same as the feedback admin list. |
| Deleting a user | History is kept. FK is `ON DELETE SET NULL`, so the row turns into a guest row; the admin page shows it as "guest / deleted user". `AccountDeletionService` needs no change. |
| Failure handling | Saving history must **never break the search**. Errors are logged and swallowed. |
| IP / user agent | **Not stored** in v1 (privacy; not asked for). See *Later*. |

## 1. Schema

### `V18__add_bowman_search_history_table.sql` — New Flyway Migration

(Latest existing migration is `V17__add_team_to_bowman_checklists.sql`; re-check the next
free number at implementation time.)

```sql
CREATE TABLE bowman_search_history (
    id           BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    search_type  VARCHAR(10)  NOT NULL,
    player       VARCHAR(100),
    year         SMALLINT,
    set_name     VARCHAR(255),
    user_id      BIGINT,
    created_at   TIMESTAMP    NOT NULL DEFAULT now(),
    CONSTRAINT chk_bowman_search_type CHECK (search_type IN ('PLAYER', 'SET')),
    CONSTRAINT fk_bowman_search_user  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE SET NULL
);

CREATE INDEX idx_bowman_search_created_at ON bowman_search_history (created_at);
CREATE INDEX idx_bowman_search_user       ON bowman_search_history (user_id);
```

Notes:

- `users.id` is `BIGINT`, so `user_id` matches.
- `year` is `SMALLINT` to match the controller's `Short year` param.
- Check `set_name` length against the `sets` table column from
  `V14__add_sets_and_bowman_checklists.sql` and use the same size.
- **Indexes from day one**, unlike `feedback`: `/bowman` is public, so this table grows with
  every visitor search (and bots). `created_at` serves "latest searches" and date-range
  reports; `user_id` serves the `SET NULL` on user delete.
- Row shape by type:

  | `search_type` | `player` | `year` | `set_name` |
  |---|---|---|---|
  | `PLAYER` | set | null | null |
  | `SET` | null | set or null | set or null (at least one of the two) |

- `spring.jpa.hibernate.ddl-auto=validate` is on, so the entity in §2.2 must match these
  column names and types exactly.

## 2. Backend

### 2.1 `enums/BowmanSearchType.java`

```java
package RGcards.SportsCardProject.enums;

public enum BowmanSearchType {

}
```

### 2.2 `entity/BowmanSearchHistory.java`

Plain `userId` column, matching `Feedback`, `Tag`, `Card`.

```java
@Data
@NoArgsConstructor
@AllArgsConstructor
@Entity
@Table(name = "bowman_search_history")
public class BowmanSearchHistory {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Enumerated(EnumType.STRING)
    private BowmanSearchType searchType;

    @Column(length = 100)
    private String player;

    private Short year;

    private String setName;

    @Column(name = "user_id")
    private Long userId;

    private LocalDateTime createdAt;
}
```

### 2.3 `dao/BowmanSearchHistoryRepository.java` + DTOs

```java
public record AdminBowmanSearchRow(
        Long id,
        BowmanSearchType searchType,
        String player,
        Short year,
        String setName,
        String username,
        LocalDateTime createdAt
) {}

public record BowmanPlayerSearchCount(String player, Long count) {}
public record BowmanSetSearchCount(Short year, String setName, Long count) {}
```

```java
public interface BowmanSearchHistoryRepository extends JpaRepository<BowmanSearchHistory, Long> {

    /** Latest searches with the username (null = guest or deleted user). */
    @Query("""
            SELECT new RGcards.SportsCardProject.dto.AdminBowmanSearchRow(
                       h.id, h.searchType, h.player, h.year, h.setName,
                       u.username, h.createdAt)
            FROM BowmanSearchHistory h LEFT JOIN User u ON u.id = h.userId
            ORDER BY h.createdAt DESC
            """)
    List<AdminBowmanSearchRow> findLatest(Pageable pageable);

    /** Most-searched players since a date, case-insensitive. */
    @Query("""
            SELECT new RGcards.SportsCardProject.dto.BowmanPlayerSearchCount(LOWER(h.player), COUNT(h))
            FROM BowmanSearchHistory h
            WHERE h.searchType = RGcards.SportsCardProject.enums.BowmanSearchType.PLAYER
              AND h.createdAt >= :since
            GROUP BY LOWER(h.player)
            ORDER BY COUNT(h) DESC
            """)
    List<BowmanPlayerSearchCount> findTopPlayers(@Param("since") LocalDateTime since, Pageable pageable);

    /** Most-searched sets since a date. */
    @Query("""
            SELECT new RGcards.SportsCardProject.dto.BowmanSetSearchCount(h.year, h.setName, COUNT(h))
            FROM BowmanSearchHistory h
            WHERE h.searchType = RGcards.SportsCardProject.enums.BowmanSearchType.SET
              AND h.createdAt >= :since
            GROUP BY h.year, h.setName
            ORDER BY COUNT(h) DESC
            """)
    List<BowmanSetSearchCount> findTopSets(@Param("since") LocalDateTime since, Pageable pageable);
}
```

`LEFT JOIN` so guest rows (`userId == null`) still appear.

### 2.4 `service/BowmanSearchHistoryService.java`

```java
@Slf4j
@Service
@RequiredArgsConstructor
public class BowmanSearchHistoryService {

    private final BowmanSearchHistoryRepository repository;

    public void recordPlayerSearch(Long userId, String player) {
        save(BowmanSearchType.PLAYER, truncate(player, 100), null, null, userId);
    }

    public void recordSetSearch(Long userId, Short year, String setName) {
        save(BowmanSearchType.SET, null, year, blankToNull(setName), userId);
    }

    private void save(BowmanSearchType type, String player, Short year, String setName,
                      Long userId) {
        try {
            BowmanSearchHistory h = new BowmanSearchHistory();
            h.setSearchType(type);
            h.setPlayer(player);
            h.setYear(year);
            h.setSetName(setName);
            h.setUserId(userId);
            h.setCreatedAt(LocalDateTime.now());
            repository.save(h);
        } catch (Exception e) {
            // History is best-effort: never fail the user's search because of it.
            log.warn("Failed to record Bowman search history", e);
        }
    }

    // + findLatest / findTopPlayers / findTopSets pass-throughs for the admin page
}
```

- The player string is trimmed (and cut to 100 chars) here, never trusted from the client
  length.
- Synchronous save is fine at current traffic (one small insert). If it ever shows up in
  response times, make `save` `@Async`.

### 2.5 `controller/BowmanChecklistController.java` — change

Add the principal (null for guests, since `/bowman` is `permitAll`) and record after the
search runs:

```java
@GetMapping
public String search(@AuthenticationPrincipal User user,
                     @RequestParam(required = false) String player,
                     @RequestParam(required = false) Short year,
                     @RequestParam(required = false) String setName,
                     Model model) {
    boolean byPlayer = player != null && !player.isBlank();
    boolean bySet = year != null || (setName != null && !setName.isBlank());
    Long userId = user == null ? null : user.getId();

    List<BowmanChecklist> results = null;
    if (byPlayer) {
        results = searchService.searchByPlayer(player);
        searchHistoryService.recordPlayerSearch(userId, player.trim());
    } else if (bySet) {
        results = searchService.searchBySet(year, setName);
        searchHistoryService.recordSetSearch(userId, year, setName);
    }
    ...
}
```

> Check that `@AuthenticationPrincipal User` resolves to the `User` entity for Google-login
> sessions too (the same way `FeedbackController` relies on it), and that it is `null` —
> not an exception — for anonymous visitors.

### 2.6 `controller/admin/AdminBowmanSearchController.java`

```java
@Controller
@RequestMapping("/admin/bowman-searches")
@RequiredArgsConstructor
public class AdminBowmanSearchController {

    private final BowmanSearchHistoryService historyService;

    @GetMapping
    public String list(@RequestParam(defaultValue = "30") int days, Model model) {
        LocalDateTime since = LocalDateTime.now().minusDays(days);
        model.addAttribute("topPlayers", historyService.findTopPlayers(since, 20));
        model.addAttribute("topSets", historyService.findTopSets(since, 20));
        model.addAttribute("latest", historyService.findLatest(100));
        model.addAttribute("days", days);
        return "admin/bowman-searches";
    }
}
```

Same shell as `admin/feedback.html` (`rg-page rg-page--wide`, `rg-table-card`).

- Period filter: **7 · 30 · 90 days** → `?days=7`.
- **Top players** table: Player · Searches.
- **Top sets** table: Year · Set · Searches (show "any" when year or set is null).
- **Latest searches** table: Time (`yyyy-MM-dd HH:mm`) · Type badge · Query (player, or
  year + set) · User (username, or muted 「訪客」 / *guest*).
- All search text is user input — **always `th:text`**, never `th:utext`.

## 4. Testing checklist

- [ ] Migration runs on a fresh DB and a prod copy; app boots with `ddl-auto=validate`.
- [ ] Guest player search → one `PLAYER` row, `user_id` NULL.
- [ ] Logged-in (local and Google) player search → row has that user's `user_id`.
- [ ] Set search with year only, set only, and both → one `SET` row each, correct nulls.
- [ ] Opening `/bowman` with no params → no row.
- [ ] If the insert fails (e.g. table dropped in a test), the search page still renders.
- [ ] Deleting a user keeps their history rows with `user_id = NULL`.
- [ ] Non-admin `GET /admin/bowman-searches` → 403; admin sees top lists and latest rows.
- [ ] Top players groups "Ohtani" / "ohtani " together.
- [ ] A search for `<script>` renders as text on the admin page.

## 5. Later (not in v1)

- **Retention**: delete rows older than e.g. 1 year with a scheduled job, if the table gets
  large.
- **Bot filtering / dedupe**: skip identical searches from the same session within a few
  seconds, or store a hashed IP to spot bots.
- **"No results" report**: add a `result_count` column to find searches that return nothing (players
  or sets missing from the checklist).
- CSV export of the history.
