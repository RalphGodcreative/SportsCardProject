# Implementation Plan: Member Feedback

## Summary

Logged-in members can send feedback — either an **opinion** (suggestion, comment) or a
**bug** report — from a new page linked in the **username dropdown** of the navbar. Admins
get a read-only list of every submission at `/admin/feedback`, linked from the same
dropdown's **Admin** section.

| Route | Who | What |
|---|---|---|
| `GET /feedback` | any authenticated user | form + the user's own past submissions |
| `POST /feedback` | any authenticated user | create one feedback row |
| `GET /admin/feedback` | `ROLE_ADMIN` | every submission, newest first, filterable by type |

No new security rule is needed: `/feedback` falls under `.anyRequest().authenticated()`
and `/admin/**` is already `hasAuthority("ROLE_ADMIN")` in `SecurityConfig`.

### Decisions

| Question | Decision |
|---|---|
| Columns | `id / type / content / user_id / created_at` — nothing else (no status, no admin reply). |
| `user` column name | **`user_id`**. `user` is a reserved word in PostgreSQL, and every other owned table (`cards`, `tags`, `search_keyword`…) already uses `user_id`. |
| `type` storage | `VARCHAR` + Java enum with `@Enumerated(EnumType.STRING)`, same as `recommendations.sport`. A `CHECK` constraint keeps the DB honest. |
| Who can submit | Authenticated users only. Anonymous visitors have no username menu, and it keeps spam out. |
| Admin actions | **List only** for v1. Delete / mark-as-handled is listed under *Later*. |
| Deleting a user | **Feedback is kept.** `user_id` is nullable with `ON DELETE SET NULL`; the admin list shows such rows as "deleted user". |

## 1. Schema

### `V16__add_feedback_table.sql` — New Flyway Migration

(Latest existing migration is `V15__seed_registration_max_users.sql`; re-check the next
free number at implementation time.)

```sql
CREATE TABLE feedback (
    id         BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    type       VARCHAR(10)   NOT NULL,
    content    VARCHAR(2000) NOT NULL,
    user_id    BIGINT,
    created_at TIMESTAMP     NOT NULL DEFAULT now(),
    CONSTRAINT chk_feedback_type CHECK (type IN ('OPINION', 'BUG')),
    CONSTRAINT fk_feedback_user  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE SET NULL
);
```

Notes:

- `users.id` is `BIGINT` (`V3__add_users_table.sql`), so `user_id` matches.
- **Feedback outlives its author.** `user_id` is nullable and the FK is
  `ON DELETE SET NULL`, so when `AccountDeletionService.deleteUserAndAllData` removes the
  user, Postgres clears `user_id` on their feedback instead of blocking the delete or
  removing the rows. `AccountDeletionService` needs **no change** — do not add a
  `feedbackRepository.delete…` call there.
- `user_id` is still always set on insert (from the logged-in principal, §2.4); `NULL`
  only ever means "the author's account was deleted".
- **No indexes for now.** Expected volume is under ~200 rows, where a sequential scan is
  faster than an index lookup. This includes the `user_id` FK, which Postgres does not
  index automatically. If volume reaches the tens of thousands, add
  `CREATE INDEX idx_feedback_user ON feedback (user_id);` in a new migration first. It
  serves both the member's history and the `SET NULL` on user delete.
- `content` capped at 2000 chars — long enough for a bug report with steps, short enough
  that the admin table stays readable. Enforced again in the service (§2.4).
- `spring.jpa.hibernate.ddl-auto=validate` is on, so the entity in §2.2 must match these
  column names and types exactly.

## 2. Backend

### 2.1 `enums/FeedbackType.java`

```java
package RGcards.SportsCardProject.enums;

public enum FeedbackType {
    OPINION,
    BUG
}
```

### 2.2 `entity/Feedback.java`

Plain `userId` column rather than a `@ManyToOne User`, matching `Tag`, `Card` and the
other owned entities.

```java
@Data
@NoArgsConstructor
@AllArgsConstructor
@Entity
@Table(name = "feedback")
public class Feedback {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Enumerated(EnumType.STRING)
    private FeedbackType type;

    @Column(length = 2000)
    private String content;

    @Column(name = "user_id")
    private Long userId;

    private LocalDateTime createdAt;
}
```

### 2.3 `dao/FeedbackRepository.java` + `dto/AdminFeedbackRow.java`

The admin list needs the submitter's username and email, so it uses a JPQL constructor
expression joined to `User` instead of N+1 lookups:

```java
public record AdminFeedbackRow(
        Long id,
        FeedbackType type,
        String content,
        String username,
        String email,
        LocalDateTime createdAt
) {}
```

```java
public interface FeedbackRepository extends JpaRepository<Feedback, Long> {

    /** The member's own history on /feedback. */
    List<Feedback> findByUserIdOrderByCreatedAtDesc(Long userId);

    /** Admin list; type == null means all types. */
    @Query("""
            SELECT new RGcards.SportsCardProject.dto.AdminFeedbackRow(
                       f.id, f.type, f.content, u.username, u.email, f.createdAt)
            FROM Feedback f LEFT JOIN User u ON u.id = f.userId
            WHERE (:type IS NULL OR f.type = :type)
            ORDER BY f.createdAt DESC
            """)
    List<AdminFeedbackRow> findAdminRows(@Param("type") FeedbackType type);
}
```

`LEFT JOIN` so feedback from deleted accounts (`userId == null`) still appears, with
`username` / `email` null.

If volume ever grows, switch `findAdminRows` to return a `Page<AdminFeedbackRow>` with a
`Pageable` — not needed at today's user count.

### 2.4 `service/FeedbackService.java`

```java
@Service
@RequiredArgsConstructor
public class FeedbackService {

    static final int MAX_CONTENT_LENGTH = 2000;

    private final FeedbackRepository feedbackRepository;

    public Feedback submit(Long userId, FeedbackType type, String content) {
        String trimmed = content == null ? "" : content.trim();
        if (type == null) {
            throw new IllegalArgumentException("請選擇類型");
        }
        if (trimmed.isEmpty()) {
            throw new IllegalArgumentException("內容不可為空");
        }
        if (trimmed.length() > MAX_CONTENT_LENGTH) {
            throw new IllegalArgumentException("內容最多 " + MAX_CONTENT_LENGTH + " 字");
        }
        Feedback feedback = new Feedback();
        feedback.setType(type);
        feedback.setContent(trimmed);
        feedback.setUserId(userId);
        feedback.setCreatedAt(LocalDateTime.now());
        return feedbackRepository.save(feedback);
    }

    public List<Feedback> findForUser(Long userId) {
        return feedbackRepository.findByUserIdOrderByCreatedAtDesc(userId);
    }

    public List<AdminFeedbackRow> findAllForAdmin(FeedbackType type) {
        return feedbackRepository.findAdminRows(type);
    }
}
```

`userId` always comes from `@AuthenticationPrincipal`, never from the form — see
`data-ownership.md`.

### 2.5 `controller/FeedbackController.java`

```java
@Controller
@RequestMapping("/feedback")
@RequiredArgsConstructor
public class FeedbackController {

    private final FeedbackService feedbackService;

    @GetMapping
    public String page(@AuthenticationPrincipal User user, Model model) {
        model.addAttribute("types", FeedbackType.values());
        model.addAttribute("myFeedback", feedbackService.findForUser(user.getId()));
        return "feedback/form";
    }

    @PostMapping
    public String submit(@AuthenticationPrincipal User user,
                         @RequestParam FeedbackType type,
                         @RequestParam String content,
                         RedirectAttributes redirectAttributes) {
        try {
            feedbackService.submit(user.getId(), type, content);
            redirectAttributes.addFlashAttribute("success", "感謝你的回饋！");
        } catch (IllegalArgumentException e) {
            redirectAttributes.addFlashAttribute("error", e.getMessage());
            redirectAttributes.addFlashAttribute("draft", content);
        }
        return "redirect:/feedback";
    }
}
```

Post/redirect/get so a refresh doesn't resubmit. On a validation error the text is
flashed back as `draft` so the user doesn't lose what they typed.

> Check how `@AuthenticationPrincipal User` resolves for Google-login sessions — use the
> same pattern `UserController` already uses so OAuth2 users work too.

### 2.6 `controller/admin/AdminFeedbackController.java`

Follows `AdminUserController`:

```java
@Controller
@RequestMapping("/admin/feedback")
@RequiredArgsConstructor
public class AdminFeedbackController {

    private final FeedbackService feedbackService;

    @GetMapping
    public String list(@RequestParam(required = false) FeedbackType type, Model model) {
        model.addAttribute("rows", feedbackService.findAllForAdmin(type));
        model.addAttribute("types", FeedbackType.values());
        model.addAttribute("selectedType", type);
        return "admin/feedback";
    }
}
```

## 3. Frontend

### 3.1 Navbar — `banner.html`

**Desktop username dropdown** (after *Edit profile*, line ~71):

```html
<li><a href="/user/edit">Edit profile</a></li>
<li><a href="/feedback">Feedback</a></li>
...
<li sec:authorize="hasAuthority('ROLE_ADMIN')"><a href="/admin/settings">Settings</a></li>
<li sec:authorize="hasAuthority('ROLE_ADMIN')"><a href="/admin/feedback">Feedback</a></li>
```

**Mobile menu** — same two additions: `Feedback` under the username section
(after *Edit profile*, line ~92, with `sec:authorize="isAuthenticated()"`), and the admin
link at the end of the Admin section (line ~113).

### 3.2 `templates/feedback/form.html` — member page

Standard page shell (`fragments/head :: styles`, `banner.html :: header`, `rg-page`):

- `rg-page-head`: title **Feedback**, subtitle e.g. 「有建議或發現問題？告訴我們。」
- Flash alerts for `success` / `error` (same markup as `admin/users.html`).
- Form `POST /feedback` (CSRF token is added automatically by `th:action`):
  - **Type** — two radio buttons / segmented control: `意見 Opinion` / `Bug 回報`.
    Default `OPINION`.
  - **Content** — `<textarea name="content" maxlength="2000" required>` pre-filled with
    `${draft}`, plus a live character counter.
  - Submit button.
- **My feedback** — a list of `myFeedback`: type badge, `createdAt` formatted
  `yyyy-MM-dd HH:mm`, content (`th:text`, never `th:utext`, with
  `white-space: pre-wrap` so line breaks survive). Empty state: 「還沒有送出任何回饋」.

### 3.3 `templates/admin/feedback.html` — admin list

Same shell as `admin/users.html` (`rg-page rg-page--wide`, `rg-table-card`).

- Filter chips / `<select>` for **All · Opinion · Bug** → `GET /admin/feedback?type=BUG`.
- Table columns: **Date** · **Type** (badge — bug in error colour, opinion neutral) ·
  **User** (username, email underneath in muted text; when `username` is null show a
  muted 「已刪除的使用者」 / *deleted user*) · **Content**
  (`th:text`, `pre-wrap`).
- Empty state row when `rows` is empty.

Content is user-supplied — **always `th:text`**, so a member can't inject HTML into the
admin's page.

## 4. Testing checklist

- [ ] Migration runs on a fresh DB and on a copy of prod; app boots with `ddl-auto=validate`.
- [ ] Local-login user and Google-login user can both open `/feedback` and submit.
- [ ] Empty / whitespace-only content and > 2000 chars are rejected with a flash error,
      draft preserved.
- [ ] Posting `type=FOO` is rejected (400 from enum binding) and nothing is saved.
- [ ] A user only sees their own submissions on `/feedback`.
- [ ] Anonymous `GET /feedback` redirects to `/login`.
- [ ] Non-admin `GET /admin/feedback` → 403; admin sees all rows, newest first; type
      filter works.
- [ ] Content containing `<script>` renders as text on both pages.
- [ ] Deleting a user (admin console and self-service) succeeds and **keeps** their
      feedback: rows remain with `user_id = NULL` and show as "deleted user" in the admin
      list.
- [ ] Both navbar links appear on desktop and mobile; admin link hidden for non-admins.

## 5. Later (not in v1)

- **Status column** (`NEW` / `IN_PROGRESS` / `DONE`) so admins can triage, and an admin
  delete button.
- **Email the admin** on new bug reports via the existing `EmailService` — keep it
  opt-in, given the email-spend concern in the project overview.
- **Rate limit** (e.g. max N submissions per user per day) if spam shows up.
- Screenshot upload for bug reports.
